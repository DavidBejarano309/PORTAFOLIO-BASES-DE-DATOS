Módulo SQL

Caso Banco Andino: transacciones, índices y SQL analítico

Fecha
13/09/2026
Equipo
David Bejarano y Samuel Camelo
Entorno
Oracle Autonomous Database, SQL Developer

Taller integrador sobre un banco ficticio. Cada ejercicio pedía provocar un problema real (pérdida de saldo, consultas lentas, bloqueos), explicarlo con evidencia del motor y corregirlo.

Abrir informe (PDF, 32 págs.)

  1. Parte 1 · 15 puntos

    Integridad transaccional y control de concurrencia

    Reproduje una actualización perdida entre dos sesiones (quedaron 800.000 en vez de 500.000) y la resolví con bloqueo pesimista, control optimista por versión y reparto de tareas con SKIP LOCKED. También documenté un bloqueo de tabla por llave foránea sin índice y un interbloqueo (ORA-00060) con su regla de prevención.

    • FOR UPDATE
    • Versionado optimista
    • SKIP LOCKED
    • Deadlock
    • FK sin índice
    Ver fragmento: cola de compensación sin colisiones 
    SELECT id_tarea, id_transferencia
  FROM tarea_compensacion
 WHERE estado = 'PENDIENTE'
   AND ROWNUM <= 5
   FOR UPDATE SKIP LOCKED;

  2. Parte 2 · 15 puntos

    Indexación y lectura de planes de ejecución

    Sobre una tabla de 200.000 transferencias medí el costo antes y después de cada índice con Explain Plan y Autotrace. Analicé el orden de columnas en índices compuestos, los índices que la consulta invalida al aplicar funciones, la selectividad, el clustering factor, los índices de cobertura y el costo de escritura de cada índice extra.

    • Explain Plan
    • Índice compuesto
    • Índice por función
    • Covering index
    • Clustering factor
    Ver fragmento: índice que sí sirve para UPPER() 
    -- Un índice normal no ayuda a: WHERE UPPER(nombre) = 'ANA'
CREATE INDEX ix_cliente_nombre_upper
    ON cliente (UPPER(nombre));

  3. Parte 3 · 10 puntos

    SQL analítico, jerárquico y MERGE

    Rankings por grupo (RANK, DENSE_RANK, ROW_NUMBER), acumulados y variaciones, jerarquías con CTE recursiva, PIVOT y LISTAGG. En el cierre mensual apliqué ajustes con MERGE excluyendo las cuentas que quedarían en saldo negativo.

    • Funciones de ventana
    • CTE recursiva
    • MERGE
    • PIVOT
    • LISTAGG
    Ver fragmento: cierre mensual con MERGE 
    MERGE INTO cuenta c
USING (
    SELECT id_cuenta, SUM(delta) AS delta
      FROM ajuste_saldo
     GROUP BY id_cuenta
) a
ON (c.id_cuenta = a.id_cuenta)
WHEN MATCHED THEN
    UPDATE SET c.saldo   = c.saldo + a.delta,
               c.version = c.version + 1
    WHERE c.saldo + a.delta >= 0;

Módulo PL/SQL

Lógica de negocio en Oracle: inventario y ventas

Fecha
03/10/2026
Equipo
David Bejarano, Samuel Camelo y Samuel Novoa
Entorno
Oracle Database 19c, SQL Developer

Sistema de inventario y ventas de una ferretería, construido por capas: desde un procedimiento simple hasta un paquete que factura un pedido completo. Cada objeto incluye su justificación de diseño.

Abrir informe (PDF, 41 págs.) Descargar código (.sql)

  1. Parte 1 · 8 puntos

    Procedimientos almacenados

    Registro de productos con validación de precio y categoría, ajuste de stock protegido contra concurrencia con FOR UPDATE y creación de pedidos que rechaza clientes inactivos o sin cupo.

    • SP_REGISTRAR_PRODUCTO
    • SP_AJUSTAR_STOCK
    • SP_CREAR_PEDIDO
    Ver fragmento: firma y validaciones del primer procedimiento 
    CREATE OR REPLACE PROCEDURE SP_REGISTRAR_PRODUCTO (
    param_codigo        IN  VARCHAR2,
    param_nombre        IN  VARCHAR2,
    param_id_categoria  IN  NUMBER,
    param_precio        IN  NUMBER,
    param_costo         IN  NUMBER,
    param_stock_minimo  IN  NUMBER DEFAULT 0,
    param_id_producto   OUT NUMBER
) IS
    vn_categoria NUMBER;
    e_precio_invalido     EXCEPTION;
    e_categoria_no_existe EXCEPTION;
BEGIN
    IF param_precio <= param_costo THEN
        RAISE e_precio_invalido;
    END IF;
    ...

  2. Parte 2 · 8 puntos

    Funciones reutilizables

    Stock disponible por bodega o consolidado, cupo de crédito y descuento por tramos con tope acumulado. Muestro además por qué una función puede invocarse desde una consulta SQL.

    • FN_STOCK_DISPONIBLE
    • FN_CUPO_DISPONIBLE
    • FN_CALCULAR_DESCUENTO

  3. Parte 3 · 10 puntos

    Procesamiento por cursores

    Cursores explícitos y parametrizados, WHERE CURRENT OF para ajustar precios, un SYS_REFCURSOR que entrega movimientos a quien lo consuma y carga masiva con BULK COLLECT y FORALL.

    • OPEN / FETCH / CLOSE
    • FOR UPDATE
    • SYS_REFCURSOR
    • BULK COLLECT
    • FORALL

  4. Parte 4 · 9 puntos

    Manejo de excepciones

    Códigos de retorno para NO_DATA_FOUND y TOO_MANY_ROWS, excepciones propias, errores de aplicación numerados, PRAGMA EXCEPTION_INIT y un registro de errores que persiste aunque la transacción principal termine en ROLLBACK.

    • RAISE_APPLICATION_ERROR
    • EXCEPTION_INIT
    • Transacción autónoma
    • SQLCODE / SQLERRM

  5. Parte 5 · 10 puntos

    Disparadores y reglas automáticas

    Normalización de datos al insertar, auditoría de cambios de precio, validación de margen, descuento automático de stock, recálculo de totales con COMPOUND TRIGGER (evitando la tabla mutante) y una vista actualizable mediante INSTEAD OF.

    • BEFORE / AFTER
    • WHEN
    • COMPOUND TRIGGER
    • INSTEAD OF

  6. Parte 6 · 5 puntos

    Caso integrador: facturación de un pedido

    PKG_VENTAS.SP_FACTURAR_PEDIDO reúne lo anterior en una sola operación: bloquea el pedido, valida su estado, acumula el subtotal, aplica el descuento, verifica el cupo y, si algo falla, vuelve a un SAVEPOINT y registra el error.

    • Paquete
    • SAVEPOINT
    • Parámetros OUT
    • Registro de errores
